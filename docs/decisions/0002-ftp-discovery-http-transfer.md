# 画像取得は「FTPで探索、HTTPで転送」の二段構成にする

- **日付**: 2026-08-08
- **ステータス**: 決定

## 背景(Context)

画像合成アプリの「画像取得」機能では、同一LAN内の機器を選び、その中のフォルダを掘ってファイルを探せるようにしたい。

当初はNetX DuoのHTTPクライアントだけで完結させる想定だったが、HTTPには「フォルダの中身を一覧する」標準的な方法が無い(GETで特定のURLのファイルを取ってくることしかできない)ことが分かった。

## 決定(Decision)

- **探索(機器一覧・フォルダ一覧の取得)**: NetX DuoのFTPクライアントを使う。FTPはLIST・CWDなど、ファイル/フォルダを一覧・移動するための機能を標準で持っている。
- **転送(実際のファイル取得)**: NetX DuoのHTTPクライアントを使う。FTPで特定したファイルのパスに対して、HTTPでダウンロードする。

通信相手はWindows PCを想定し、標準機能のIIS(FTPサイト・既定のWebサイト)で両方を受ける。

## 検討した代替案(Alternatives)

- **HTTPだけで完結させる**: サーバー側にファイル一覧を返す簡易的な仕組み(決まったURLでファイル名一覧のテキスト/JSONを返す等)を自作すれば可能。標準的ではないが実現できる。今回は、標準機能で完結する構成を優先して見送った。
- **FTPだけで完結させる**(一覧も転送もFTPのRETRで行う): 一番シンプルだが、そもそもこのプロジェクトでHTTP(+ Npcapによる実通信)を検証したかった動機と噛み合わなくなる。
- **FTPとHTTPを、それぞれ別の独立した機能として両方提供する**(例: 「機器から探す(FTP)」「URLを直接入力する(HTTP)」の2択をユーザーに見せる): 機能としては成立するが、「同じ画像取得という目的のために、なぜ2つの方法があるのか」がユーザーから見て分かりにくい。今回は、1つのフローの中で役割を分担する(探索はFTP、転送はHTTP)形の方が筋が通ると判断した。

## 結果・影響(Consequences)

- NetX DuoのFTPクライアントアドオンとHTTPクライアントアドオンの両方を実装することになり、実装量はHTTPのみの場合より増える
- 「探索」と「転送」で担当プロトコルが明確に分かれるため、機能としての説明はしやすい
- 通信相手のWindows PCで、IISのFTPサイトと既定のWebサイトの両方を有効にしておく必要がある(標準ではオフ)
- FTPで見つけたファイルパスから、対応するHTTP URLを組み立てられることが前提になる(同じホスト・同じ相対パスで両方公開されている想定)
