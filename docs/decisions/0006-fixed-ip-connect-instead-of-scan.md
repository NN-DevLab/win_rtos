# 機器検索(スキャン)をやめ、IPアドレス直接指定に変更する

- **日付**: 2026-08-10
- **ステータス**: 決定

## 背景(Context)

[ADR-0005](0005-subnet-scan-device-discovery.md)で「自分のサブネット内を総当たりスキャン(pingで絞り込んでからFTP接続)」という機器検索の方式を決めたが、実際の利用シーンを見直すと、[方式設計書のデータフロー](../design/architecture.md#データフロー通信方式)に書いた通り「同一LAN内の別PC1台」または「自分自身(localhost)」を相手にすることしか想定していない。つまり、複数の機器の中から探し回るシーンはそもそも存在しない。

このプロジェクトの主目的は「ThreadX・NetX Duo・FileX・GUIXの動きを一通り学ぶこと」であり、サブネット計算・ping生存確認・254回ループといったスキャンの実装自体は、その学習目的から外れた複雑さを持ち込んでいた。

## 決定(Decision)

機器検索・機器一覧をやめ、ユーザーがIPアドレスを直接指定する方式に変更する。

- S02(画像取得画面)に「接続」ボタンを置き、押すとD06(接続先入力ダイアログ)が開く
- D06でIPアドレスを入力して「接続開始」を押すと、ダイアログは閉じてS02に戻り、S02側で接続状態(「接続中...」→「接続済み」/「接続失敗」)を表示する
- 接続が成功したら、そのままルートフォルダの中身をフォルダ一覧に表示する(以降のフォルダを掘る操作は変更なし)

## 検討した代替案(Alternatives)

- **[ADR-0005](0005-subnet-scan-device-discovery.md)のサブネット総当たりスキャン(元の決定)**: 実際の利用シーンに対して過剰な仕組みだった。今回置き換えの対象
- **固定のホストリスト(設定ファイル等)を使う**: ADR-0005の検討時にも挙がった案。ユーザー操作で毎回入力する手間は無くなるが、設定ファイルの仕組みを別途用意する必要があり、今回は「その場でIPアドレスを入力する」方がシンプルと判断した

## 結果・影響(Consequences)

- ADR-0005で決めたサブネット計算・ping生存確認・FTP接続ループの実装は不要になった
- ダイアログが1つ増える(D06)。ダイアログの開閉自体はD01と同じ`show`/`front_move`/`hide`の仕組みをそのまま使える
- 共有データの構造体は、機器一覧用の`device_list_t`(IPアドレスの配列)から、接続状態+フォルダ一覧を持つ構造体に置き換える(詳細設計書参照)
- [sequence-device-search.svg](../design/images/sequence-device-search.svg)は実態と合わなくなったため削除し、新しいシーケンス図に置き換える
