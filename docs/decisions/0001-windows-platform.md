# プラットフォームにWindows(Win32シミュレータ)を採用する

- **日付**: 2026-08-08
- **ステータス**: 決定

## 背景(Context)

Eclipse ThreadXおよびそのエコシステム(NetX Duo・FileX・GUIX・USBX)を検証・学習したい。既存のpico_rtos(Raspberry Pi Pico/RP2040)プロジェクトはあるが、以下の課題があった。

- USBXがRP2040向けにはそもそもサポートされておらず、TinyUSB経由での代替実装になっている
- GUIXを表示するディスプレイがPico側の構成に無い
- コンポーネントごとに動作確認できる実機を揃えようとすると、購入コストと調達の手間がかかる

## 決定(Decision)

Windows上のWin32シミュレータを使う。Eclipse ThreadXはThreadX・NetX Duo・FileX・GUIXそれぞれに公式のWin32ポート(`ports/win32/`)を提供しており、これを利用する。

## 検討した代替案(Alternatives)

いずれも「不可能」というわけではなく、実現には相応の追加コスト・時間がかかるため見送った。

- **実機(STM32 Discoveryシリーズ等)を購入して検証**: LCD・Ethernet・SDスロット・USB OTGが揃ったモデルを選べば全コンポーネントを検証できる。ただし購入コストと調達の待ち時間が発生し、今すぐには試せない。
- **Raspberry Pi Pico(RP2040)を使う**: 既存のpico_rtosがある。USBXは公式非対応だが、pico_rtos自体がTinyUSB経由の代替実装で回避しているように不可能ではない。GUIXも表示器を追加配線すれば動かせる可能性はある。ただし、いずれも追加のハードウェア調達と実装の手間が大きく、今回の検証目的に対して割に合わない。
- **WSL(Linux)を使う**: ThreadX/NetX DuoにはLinux向けポートもあり、動かせないわけではない。ただしWSL2はデフォルトでNAT越しのため生パケットアクセスに追加設定が必要、GUI表示もWSLg経由でひと手間かかるなど、セットアップの手間の割にWindowsで完結する場合と比べて得られるものが少ない。

## 結果・影響(Consequences)

**得られるもの**

- 追加のハードウェア購入なしで、4つのコンポーネントすべてを1台のPC上で動かして検証できる
- GUIXの表示を実際のモニタ上でそのまま確認できる
- NetX DuoはNpcap経由で実際の外部通信(実サイトへのHTTPアクセス等)まで検証できる

**実機でしか検証できない項目(トレードオフとして残る)**

- USBXは実USBデバイスとの通信をこの環境では検証できない(Win32シミュレータは疑似デバイス同士の通信のみ)
- RP2040など組み込みターゲット固有の制約(メモリ量、周辺機能の実装)はここでは再現できない
- **タイミング・リアルタイム性**: Windowsのタイマー精度・スレッドスケジューラの上で動くため、実機の割り込みタイミングやクロック速度とは異なる。リアルタイム制約がシビアな処理が実際に間に合うかはここでは検証できない
- **メモリ制約**: PCの潤沢なメモリで動くため、実機のRAM/Flash容量(数百KB〜数MB程度)の制約下で発生するスタックオーバーフロー等のバグを見逃す可能性がある
- **実際の周辺機器・ドライバ**: SPI・UART・実ディスプレイコントローラ・実センサーなどのハードウェア固有のドライバコードは、Windows版では別物(GDI描画、Npcap等)に置き換わっており、実機用ドライバのコード自体はここでは一切テストされない
- **相性問題**: 実際のUSBデバイスやネットワーク機器・ケーブルとの相性(ベンダー固有の癖、信号品質等)は、シミュレータでは再現できない

いずれも、実機でしか検証できない項目は今後実機を用意して別途確認する必要がある。
