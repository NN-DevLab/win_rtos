# 日本語フォント対応まで画面表示を英語/ローマ字の仮表示にする

- **日付**: 2026-08-14
- **ステータス**: 決定

## 背景(Context)

S01(メイン画面)の実装中、説明文プロンプトと2つのボタンラベルに日本語文字列を設定したところ、文字が一切描画されない不具合が発生した。

原因を`repos/guix`のソースを読んで調査した結果、GUIXのデフォルトシステムフォント`_gx_system_font_8bpp`([common/src/gx_system_font_8bpp.c](../../repos/guix/common/src/gx_system_font_8bpp.c))はグリフ範囲が`0x0020`〜`0x007e`(半角英数記号のみ)で、日本語のグリフを一切持たないことが判明した。背景の塗りつぶしなど他の描画は正常だったため、テキスト描画だけがこの理由で無言でスキップされていた。

日本語グリフを含むフォントリソースを使うには、GUIX Studio(`repos/guix/guix_studio`、MFCベースのWindows GUIツール)でTrueTypeフォントから変換する必要がある。実際にGUIX Studioのビルドは完了させた(MFCコンポーネント追加、プラットフォームツールセットの`v143`→`v145`修正、Windows SDKの`IMAGE_INFO`型衝突を`GX_STUDIO_IMAGE_INFO`へのリネームで回避、が必要だった)が、フォント変換自体はプロジェクト作成・TrueTypeパス指定・文字範囲指定・生成・組み込みという複数ステップの一回限りの作業になり、S01の実装を止めてまで今やる規模ではないと判断した。

## 決定(Decision)

日本語フォント対応が完了するまで、画面上のテキストは英語/ローマ字の仮表示にする。

- 該当箇所には理由をコメントで残す(例: [s01_main.c](../../app/s01_main.c)の各`text_set`呼び出し)
- 対応するGUIXのコード上の日本語文字列は、コミット時のコミットメッセージやコメントに残し、後で置き換えやすくする

## 検討した代替案(Alternatives)

- **今すぐGUIX Studioで日本語フォントを生成する**: 実施すれば根本解決だが、GUI操作を伴う一回限りの作業であり、他画面の実装やレイアウト確認を止めてまで今やる理由がなかった。後回しにしても手戻りは小さい(フォント追加後は`font_table`にエントリを足して各ウィジェットの`font_id`を差し替えるだけ)
- **英語のまま本番仕様にする**: このアプリは日本語UIを前提に設計している([functional.md](../design/functional.md)等)ため却下

## 結果・影響(Consequences)

- S01を含む今後の画面実装は、テキスト内容そのものはひとまず英語/ローマ字で進める
- 日本語フォント対応が完了するまで、実機(GUIX Studio生成物を組み込んだ状態)での見た目確認はできない
- 対応時の作業は概ね次の手順になる: GUIX StudioでTrueTypeフォントを日本語文字範囲(ひらがな・カタカナ・CJK統合漢字)で変換 → 生成された`_resources.c`のフォント定義を[gui_main.c](../../app/gui_main.c)の`font_table`に追加 → 各画面の`gx_prompt_font_set()`/`gx_text_button_font_set()`等でフォントIDを差し替え → 仮の英語文字列を日本語に戻す
